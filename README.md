# astrbot_plugin_qzone_reader

把 QQ空间说说转发给 bot，自动读取、总结，并且**内容会进入会话历史**，之后可以继续追问讨论。

不需要任何指令 —— 转发动作本身就是触发条件。

## 为什么需要它

QQ空间说说的分享卡片上只有一句标题和摘要，模型看不到正文。**转发（repost）更麻烦**：卡片上能拿到的往往只有转发者自己写的那句短评语，被转发的原文完全不在卡片里。

典型场景：

> 某人转发了一篇瓜条，只写了句「现在的小朋友玩的真花」。
> 卡片上只有这 12 个字，bot 完全不知道那篇瓜条讲了什么。

本插件会把说说（**含被转发的原文**）的完整正文、配图、作者、时间取出来，注入本轮对话。

## 安装

在 AstrBot 的插件目录下：

```bash
cd /AstrBot/data/plugins
git clone https://github.com/insolitude610/astrbot_plugin_qzone_reader
```

也可以在 WebUI 插件页填写仓库地址安装，或上传插件压缩包。

依赖只有 `aiohttp`，AstrBot 本体已自带，**无需额外 pip install**。装好后在 WebUI 重载插件即可。

## 使用

把说说转发给 bot：

1. 在 QQ空间里点说说的「分享」→ 发送给 bot；
2. bot 自动读取并总结；
3. 接着追问即可，比如「作者是什么情绪」「帮我梳理一下时间线」。

也支持直接粘贴链接：`https://h5.qzone.qq.com/ugc/share?...` 或 `https://mobile.qzone.qq.com/l?...`

### 群聊里引用分享卡片

**可以。** 群聊里常见这个用法：

```
群友A：［QQ空间说说分享卡片］
群友B：［引用上面那条］@bot 这瓜啥情况
```

bot 会去读**被引用那张卡片**里的说说，正常总结。原理是 AstrBot 在处理引用消息时会把被引用的消息内容抓回来（默认行为），所以卡片信息拿得到。

几点说明：

- 引用时必须 **@bot 或带唤醒前缀**，否则群聊里 bot 不会被唤醒 —— 这是 AstrBot 的通用规则，跟本插件无关。
- 你**不需要先让 bot 看一遍**原卡片。直接引用 + @它就行，插件会当场解析。
- 引用**纯文本消息**（不是卡片）时不会触发，因为没有可解析的分享链接。
- 嵌套引用（引用一条引用了卡片的回复）也能找到，最多递归 5 层。

### 转发的说说

转发场景下内容会分两层呈现，bot 两层都能看到：

```
转发者：XXX          转发时间：...
转发语：现在的小朋友玩的真花

—— 以下是这条说说转发的原内容 ——
原文作者：YYY        原文发布时间：...
原文正文：（完整原文）
原文配图：共 N 张
```

配图会优先附带**原文的图**，因为转发场景下原文图才是主体。

## 登录态从哪来

QQ空间没有开放接口，读取说说需要账号 Cookie。插件按以下顺序尝试：

1. **NapCat 自动获取**（默认）
   通过 OneBot 的 `get_cookies(domain="user.qzone.qq.com")` 直接向协议端索取，成功后缓存（默认 600 秒，见 `cookie_ttl`）。登录态失效时会自动清缓存重取一次。
2. **手动 Cookie 兜底**
   把 `cookie_source` 设为 `manual`，或在自动获取失败时使用 `cookies_str`。

抓手动 Cookie：电脑浏览器登录 QQ空间 → F12 → Network → 刷新 → 任意请求 → 复制请求头里的完整 `Cookie`，必须包含 `uin`、`skey`、`p_skey`。

> **Cookie 等同于账号密码。** 它只保存在你的 AstrBot 配置里，不会外发，也建议限制 `group_whitelist` 避免群友借用你的登录态。请勿贴到公开群聊或截图分享。

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `cookie_source` | `"napcat"` | `napcat` 走协议端自动获取；`manual` 只用 `cookies_str` |
| `cookies_str` | `""` | 手动 Cookie，任何模式下都作为兜底 |
| `cookie_ttl` | `600` | 自动获取的 Cookie 缓存秒数，`0` 表示不缓存 |
| `read_full_feed` | `true` | 关闭后只用卡片上的文字，不发任何网络请求 |
| `max_images` | `4` | **最终交给模型的图片总数上限**（切片计入其中）。`0` 表示不带图。无隐藏上限，但张数越多 token 消耗越大 |
| `slice_tall_images` | `true` | 长截图切片，见下文。这是能否读出瓜条配图细节的关键 |
| `slice_max_height` | `0` | 每片目标高度（像素），`0` 用默认 1280。调小更清晰但片数更多 |
| `context_mode` | `"keep"` | 上下文保留，见下文 |
| `summarize_mode` | `"brief"` | 总结模式，见下文 |
| `group_whitelist` | `[]` | 只在这些会话生效（群号/QQ号），留空表示全部会话 |
| `notify_on_failure` | `true` | 读不到正文时是否告知用户。关闭则静默降级，只把卡片文字交给模型且不提失败 |

### 上下文保留 `context_mode`

决定说说内容**是否留在会话历史里**：

| 取值 | 行为 | 适合 |
| --- | --- | --- |
| `keep` | 说说原文与配图随本轮消息写入会话历史，后续追问时模型仍能看到内容 | 默认。你希望就这条说说继续聊下去 |
| `once` | 只在**本次回复**时给模型看，不写入历史 | 看一眼就完事的瓜条。避免长瓜条和它的切图长期占着上下文，把后续对话的额度挤掉 |

两者在**当次回复**上的表现完全一样 —— 都是完整读取、照 `summarize_mode` 总结。差别只在**下一轮**：

- `keep`：你可以直接问「第二点展开说」，它记得
- `once`：它已经看不到原文了。想继续聊得重新转发一次

实现上，`once` 会把注入的文本与图片都标记为「临时内容块」，AstrBot 落历史时会把它们过滤掉。

> **两个诚实的说明：**
> 1. 你发的那条**卡片消息本身**由 AstrBot 自行入库，本插件无法控制 —— 它仍会留在历史里，只是内容是个空壳卡片，不含说说正文。
> 2. **bot 当次的回复仍然会保存**。`once` 只影响「说说内容」，不影响对话记录本身。

### 长截图切片 `slice_tall_images`

QQ空间的瓜条配图几乎都是**聊天记录长截图**，典型尺寸 `640x3799`、`476x4096`。

这类图直接发送会被视觉模型等比缩放到像素上限（通常约 1024px），**宽度从 640 压到约 170** —— 里面的聊天文字彻底糊掉，模型实际上等于没收到图。

开启切片后，插件会保持宽度不变、只按高度切成多段（段间留重叠避免切断消息）再发送。上面的例子会切成 4 片 `640x1280`，文字保持清晰，模型就能真正读到图里的内容。

代价与约束：

- **片数计入 `max_images`**。一本 14 张长图的瓜条理论能切成 50+ 片，所以最终张数受该上限约束，不会失控。
- 每张图最多切 12 片；高瘦比不足 1.5 倍的正常竖图不会被切。
- token 消耗明显上升。只想让它"看懂文字"的话可以把 `max_images` 设小（如 `4`），或干脆关掉切片。

> 如果你发现 bot 总结瓜条时只说得出"某某开撕某某"这类笼统内容，八成是配图没被有效阅读 —— 这条正是为此而设。

### 总结模式 `summarize_mode`

这一项决定 bot 拿到说说内容后**怎么回应**，是整套配置里最影响体验的一个：

| 取值 | 行为 | 适合 |
| --- | --- | --- |
| `off` | **不加任何指令**。bot 只知道内容，怎么回完全由它的人格决定，可能只聊一句、也可能问你问题 | 你只想让它"看懂"，具体聊什么由你带节奏。**注意这不代表 bot 不回复**，是否回复由 AstrBot 的唤醒规则决定 |
| `brief` | 附一句「**先简要总结**再说说你的看法」，偏要点式，话不多 | 默认。想要"转发就有一句总结"，又不希望太长 |
| `full` | 明确要求 bot **用自己的人格把这条动态完整总结一遍**：谁说的、发布时间、来龙去脉、涉及哪些人及各自立场、作者情绪、配图内容、以及哪里信息不全 | 长瓜条、需要一次看全的内容。想让它认真梳理而不是随便聊两句 |

`full` 模式下的指令要点（在 `main.py` 的 `FULL_SUMMARY_INSTRUCTION`）：

```
1. 谁说给谁听的、发布与转发的时间；
2. 事情的来龙去脉，按条理把要点讲清楚；
3. 涉及哪些人或方，各自的主张与立场；
4. 作者的情绪与意图；
5. 若有配图，说明图片内容与正文的关系；
6. 信息不完整或属于单方说法的地方，明确指出来，不要替作者补全。
总结之后可以简短说一句你的看法，但总结本身要完整。
```

第 6 条是刻意加的：瓜条类内容往往是单方说法，这条约束能减少 bot 顺着原文情绪跑偏。

**三种模式的内容都会进入会话历史**，之后可以继续追问，区别只在 bot 第一句回得多完整。

> 旧版配置里的 `auto_summarize`（布尔）仍然兼容：`true` 等价于 `brief`，`false` 等价于 `off`。新键 `summarize_mode` 优先。

## 工作原理

```
转发卡片 / 引用卡片并 @bot / 粘贴链接
      │
      ▼
① 识别链接   递归扫描整条消息链（含被引用的 Reply.chain）
      │        Comp.Json.data · Plain 文本 · raw_message 兜底
      │        并还原 QQ 卡片里的 &#44; 转义
      ▼
② 取登录态   NapCat get_cookies → 手动 Cookie
      │
      ▼
③ 短链解析   跟随 302 跳转到 h5.qzone.qq.com/ugc/share
      │        拿到 res_uin / cellid
      ▼
④ 读分享页   解析页面内嵌的 FrontPage 数据
      │        cell_summary 正文 · cell_pic 配图 · cell_original 被转发的原文
      │        （失败则退回 emotion_cgi_msglist_v6 列表接口）
      ▼
⑤ 配图处理   长截图切片（按 max_images 预算）
      │
      ▼
⑥ 注入       on_llm_request → extra_user_content_parts + image_urls
      │        context_mode=once 时标记为临时内容，不落历史
      ▼
   AstrBot 组装为同一条 user 消息 → 写入会话历史 → 可继续讨论
```

第 ⑥ 步是「能持续讨论」的关键：AstrBot 会把「用户消息 + 额外内容块 + 图片」组装成**同一条 user 消息**并写入会话历史。所以说说内容不是一次性提示，而是真正留在了上下文里。

（`context_mode=once` 时，第 ⑥ 步会把内容标记为临时块，AstrBot 落历史时把它过滤掉 —— 所以这种模式下说说内容不会留在后续上下文里。）

## 排障

先在 AstrBot 日志里搜 `[qzone_reader]`，插件的关键步骤都会打日志。

| 现象 | 原因与处理 |
| --- | --- |
| 日志出现 `没有可用的 QQ空间登录态` | NapCat 未在线或 QQ 已掉线。恢复登录，或手动填 `cookies_str` |
| 日志出现 `放弃读取` | 分享链接里没有可定位说说的参数。把日志里那行链接发出来以便跟进 |
| 日志出现 `分享页没取到内容，改走动态列表接口兜底` | 分享页未返回数据（权限较严的说说）。若列表接口也定位不到，会降级为卡片文字 |
| bot 说读不到内容 | 多为登录态失效，按第一行处理 |
| 总结里没有图片内容 | 模型不支持图片输入时 AstrBot 会跳过图片；把 `max_images` 设为 `0` 让插件只发文字 |
| 只在某些群生效 | 用 `group_whitelist` 填群号 |
| 群聊里 @bot 没反应 | 确认确实 @ 到了 bot（或被唤醒前缀命中）。日志里没有 `检测到 QQ空间分享` 就说明插件没被触发，问题在唤醒环节 |
| 引用卡片后没反应 | 日志里搜 `检测到 QQ空间分享`。没有则说明协议端没取回被引用的原消息（原消息可能已删除），改用直接转发 |
| 不想每次都被回「没读到」 | 把 `notify_on_failure` 设为 `false` |
| 总结瓜条时内容很笼统 | 多半是配图没被有效阅读。确认 `slice_tall_images` 已开启，并把 `max_images` 调大（长截图切片后片数较多，4 片可能只够读 1 张图） |
| 上下文被长瓜条占满 | 调小 `max_images`，或关闭 `slice_tall_images`；说说正文本身无法截断，这是设计取舍 |
| 报了没装 Pillow | 切片依赖 Pillow。AstrBot 本体已依赖它，正常不会缺；确实缺就 `pip install pillow`，插件会自动退回发原图 |

## 已知限制

- 依赖 **aiocqhttp / OneBot v11**（NapCat、LLOneBot 等），其他平台适配器不生效。
- 群聊里**必须 @bot 或带唤醒前缀**才会响应，这是 AstrBot 的通用唤醒规则。
- 引用分享卡片时依赖协议端能取回被引用的原消息（AstrBot 的 `get_reply` 默认开启）。若原消息已被删除或 `get_msg` 失败，引用方式就读不到。
- 只能读取**你的账号有权限看到**的内容；登录态失效时读不到好友可见的说说。
- 分享页对部分权限较严的说说可能不返回数据，此时会退回列表接口；两条路都失败则降级为卡片文字。
- 视频只记录「含视频 N 个」，不解析视频内容（`cell_video()` 已能取地址，但未接入注入）。
- 长文本瓜条注入后会占用较多上下文，受模型上下文长度限制。开启长截图切片后图片张数增加，token 消耗更明显 —— 可用 `context_mode=once` 或调小 `max_images` 缓解。
- 长截图切片参数（每片 1280px、高瘦比 1.5 倍判据）是**经验值**，未针对具体模型实测校准。不同视觉模型的上限不同，必要时用 `slice_max_height` 调整。
- 使用的是 QQ空间 Web 端非公开接口，腾讯调整页面结构时可能需要跟进修复。
